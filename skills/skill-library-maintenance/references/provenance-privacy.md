# Source provenance, privacy and truthful freshness

## Stable inputs and actual verification

Inspect the current producer/schema/verifier rather than globally replacing release numbers or carrying forward old counters. Keep prepare-only work outside ingested/published namespaces and test a not-ready result when required final artifacts are absent. An offline structural check does not prove an unexercised live branch.

For an authorized fresh public verification, preserve actual fetched bytes and the request/cache receipt: method/status/final URL identity, complete-body/range status, expected digest, byte count and parsed content as required. A new destination filename or cache API invocation alone is not evidence of a new network/origin GET. Distinguish rehashing retained bytes from fetching again; do not delete caches to manufacture apparent freshness.

Compare complete inherited objects/arrays, including original serialized slices when a byte-preservation contract requires them. Stable direct/nested pins must resolve to expected bytes and intended scope. Do not pick a plausible alternative path, silently repin active-writer drift or exempt all mutable records. Preserve original descriptors and document any narrow historical mutable exclusions.

Current events, inherited counters and verification requests need separate accounting. Missing completion events stay unknown. A receipt accepting an action is not proof of email delivery, forwarding, rights, publication or final closure. Check the actual schema and authoritative lifecycle evidence; words like finished in task text are not process-state evidence.

## Conservative privacy findings

Collector matches are candidates, not proven credentials. Classify each against exact source, typed keypath and embedded representation without exposing protected values. Public labels can be false positives, but a global benign-word/key/value allowlist can conceal a real password or token elsewhere.

Any permitted exception must bind the exact revision, path, scalar type and expected value/digest, fail on drift and remove only that occurrence in a parsed in-memory review view. Preserve original inputs and test recollection so another occurrence in Authorization/cookie/token/password/CSRF fields remains protected. Unknown records keep normal protection and the final leak guard stays intact.

Check raw, URL-encoded/decoded, HTML-entity and JSON layers where relevant, including generated metadata/descriptors rather than only old reports. Never include actual protected values in stdout, request files, examples or test diffs. A traceback or failed rich assertion can leak them without an explicit print; use synthetic fixtures and safe count/boolean diagnostics for authorized real-source scans. Short-value hashing is minimization, not anonymization.

A public draft review does not require reading live credential stores. Use an explicitly authorized private guard interface if a real-source release needs one. Report pattern checks, substantive review and final whole-artifact guards separately; do not claim the last gate merely because the first two passed.
