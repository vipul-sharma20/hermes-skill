# Distribution audit patterns

An audit is read-only unless implementation or publication is separately authorized. Resolve the active profile and actual repo remote/working tree, and check the remote branch read-only before claiming the local checkout is current. No cross-profile reads/writes or KB edits are implicit.

Inventory whole packages and helpers, not just the prompt index. Bundled manifest membership, hub/external provenance and content drift answer different questions. Absence from today's upstream checkout does not prove custom authorship. Use installed hashing rules and exclude runtime caches; do not freeze a particular algorithm as a universal contract.

Follow the complete caller chain: optimizer support is not enough if a publisher still uses the wrong format, extension or MIME. A reduced-PATH executable fallback should be ported without discarding public validation, safe request files, subprocess timeouts, dedicated credentials or atomic state. Check top-level side effects before importing scripts. Use generated fixtures and recording clients for offline behavior probes, labeling them as tests rather than live evidence.

Prefer targeted changes over copying a private package. Parameterize paths/endpoints, declare dependencies, bundle helpers and tests, and remove identities, host details, channel IDs, itineraries, credentials and live state. Publishing a repo change does not update every installed profile. File mtimes indicate neither feature chronology nor remote freshness.

Inspect documented offline tests and add probes for actual identified gaps. Dry-run flags may leave auxiliary state or network side effects; read the code first. Do not run bridge ticks, publishers or live monitors just to audit packaging. Report exact behavior differences, tested scope, remaining portability/privacy blockers and recommended order. Do not publish or push merely because an item is repo-worthy.
