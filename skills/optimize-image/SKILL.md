# Optimize Image

Re-encode images as JPEG under a byte budget while preserving as much quality and resolution as possible. The helper fixes EXIF orientation, flattens transparency onto white, and optionally reads HEIC or HEIF originals. The bundled executable is `scripts/image_optimizer.py`.

## When to Use

- The user asks to compress, resize, or make an image web-sized.
- An attachment must fit an email, chat, form, or API size limit.
- A phone image needs orientation correction or HEIC conversion.

Don't use when the user requires lossless output, preserved transparency, animation, or original metadata.

## Prerequisites

- `uv` available on `PATH`.
- `Pillow`; `pillow-heif` is optional unless HEIC or HEIF input is required.

Use `uv run --with pillow --with pillow-heif` so dependencies stay outside Hermes's shared environment.

## How to Run

For one image:

```python
terminal(
    command='uv run --with pillow --with pillow-heif "${HERMES_SKILL_DIR}/scripts/image_optimizer.py" input.png --out output.jpg --max-bytes 500000',
    timeout=180,
)
```

For multiple images:

```python
terminal(
    command='uv run --with pillow --with pillow-heif "${HERMES_SKILL_DIR}/scripts/image_optimizer.py" one.png two.heic --out-dir optimized --max-edge 1920',
    timeout=300,
)
```

Options:

- `--max-bytes N`: output ceiling in bytes; default `950000`.
- `--max-edge N`: longest output edge; default `1920`, minimum `320`.
- `--quality N`: starting JPEG quality from `45` to `95`; default `88`.
- `--out PATH`: output path for one input.
- `--out-dir DIR`: output directory for one or more inputs.

## Procedure

1. Confirm whether the user specified a byte limit, maximum dimensions, output location, and whether JPEG conversion is acceptable. Done when all required constraints are explicit or defaults are accepted.
2. Run the helper through `terminal` with every input path and the selected limits. Done when the command exits successfully and prints one absolute output path per input.
3. Read stderr's before-and-after summary and verify every output is within the requested byte limit. Done when every generated file meets the constraint.
4. Return the output paths so Hermes delivers the files as attachments. Add `[[as_document]]` when the user needs the exact generated bytes rather than a platform-recompressed preview.

## Pitfalls

- JPEG output removes transparency and animation.
- HEIC and HEIF decoding requires `pillow-heif`.
- An unrealistically small byte budget may require dimensions below the `320px` safety floor and will fail explicitly.
- Chat platforms may recompress image previews; use document delivery for exact-size artifacts.
- Never overwrite the source unless the user explicitly requests it.

## Verification

- [ ] Output opens as a valid JPEG.
- [ ] Output byte size is at or below `--max-bytes`.
- [ ] Longest edge is at or below `--max-edge`.
- [ ] Orientation is visually correct.
- [ ] Every requested input produced exactly one output.
