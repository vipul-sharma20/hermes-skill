# Optimize Image

Re-encode images as JPEG under a byte budget while preserving as much quality and resolution as possible. The helper fixes EXIF orientation, flattens transparency onto white, and optionally reads HEIC or HEIF originals. The bundled executable is `scripts/image_optimizer.py`.

## When to Use

- The user asks to compress, resize, or make an image web-sized.
- An attachment must fit an email, chat, form, or API size limit.
- A phone image needs orientation correction or HEIC conversion.

Don't use when the user requires lossless output, preserved transparency, animation, or original metadata.

## Prerequisites

- `uv` available on `PATH`.
- `Pillow`; `pillow-heif` is optional unless HEIC or HEIF input is required.

Use `uv run --with "pillow>=11,<13" --with "pillow-heif>=1,<2"` so dependencies stay outside Hermes's shared environment and major versions remain bounded.

## How to Run

Use the shell-safe request-file interface. Start from `templates/request.example.json`, then write a session-specific JSON request with `write_file`. Keep every user-controlled input and output path inside JSON; never interpolate those paths into a terminal command.

For one output, set `out`. For multiple outputs, omit `out` and set `out_dir` instead. Then run only the fixed, system-generated request path:

```python
terminal(
    command='uv run --with "pillow>=11,<13" --with "pillow-heif>=1,<2" "${HERMES_SKILL_DIR}/scripts/image_optimizer.py" --request "${HERMES_HOME:-$HOME/.hermes}/cache/optimize-image-${HERMES_SESSION_ID}.json"',
    timeout=300,
)
```

Request fields:

- `sources`: required array of input paths.
- `out`: output path for exactly one input.
- `out_dir`: output directory for one or more inputs.
- `max_bytes`: output ceiling in bytes; default `950000`.
- `max_edge`: longest output edge; default `1920`, minimum `320`.
- `quality`: starting JPEG quality from `45` to `95`; default `88`.

## Procedure

1. Confirm whether the user specified a byte limit, maximum dimensions, output location, and whether JPEG conversion is acceptable. Done when all required constraints are explicit or defaults are accepted.
2. Write a session-specific request JSON with every source and destination path represented as JSON strings. Done when no user-controlled value appears in the terminal command.
3. Run the helper through `terminal` using only `--request` and the fixed request-file path. Done when the command exits successfully and prints one absolute output path per input.
4. Read stderr's before-and-after summary and verify every output is within the requested byte limit. Done when every generated file meets the constraint.
5. Return the output paths so Hermes delivers the files as attachments. Add `[[as_document]]` when the user needs the exact generated bytes rather than a platform-recompressed preview.

## Pitfalls

- JPEG output removes transparency and animation.
- HEIC and HEIF decoding requires `pillow-heif`.
- An unrealistically small byte budget fails before a proportional resize would cross the `320px` safety floor.
- Multiple sources with the same filename stem are rejected in `out_dir` mode instead of overwriting each other.
- Never interpolate user-controlled paths into a terminal command; keep them in the JSON request file.
- Chat platforms may recompress image previews; use document delivery for exact-size artifacts.
- Never overwrite the source unless the user explicitly requests it.

## Verification

- [ ] Output opens as a valid JPEG.
- [ ] Output byte size is at or below `--max-bytes`.
- [ ] Longest edge is at or below `--max-edge`.
- [ ] Orientation is visually correct.
- [ ] Every requested input produced exactly one output.
